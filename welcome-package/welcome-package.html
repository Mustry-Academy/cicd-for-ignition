03 · SYSTEM REQUIREMENTS
Before you do anything else

What to install.

Everything runs locally on Docker. Install it all, then run the preflight script (next page).

Docker Desktop≥ 24
Give it ≥ 8 GB RAM and ≥ 4 CPUs (Settings → Resources), and use the WSL2 backend on Windows. A free Docker Hub login helps — anonymous pulls are rate-limited, worse on shared networks. docker.com
Git≥ 2.40
Set user.name / user.email, and leave core.autocrlf off (or input) — CRLF checkouts break the lab scripts. git-scm.com
Python≥ 3.10
Needed for the lab scripts and linters. Must create a venv with pip: on Ubuntu/WSL install python3 and python3-venv; on macOS, brew install python.
A GitHub account
Free — every lab pushes to your own fork. Create one at github.com and verify your email address first.
GitHub CLIgh
Run gh auth login -s workflow — without that scope GitHub rejects pushes that touch a workflow file. Accept its offer to set up git or upload an SSH key so git push works. cli.github.com
VS Code
Plus the Docker extension, with code on your PATH. Any editor works, but our demos use VS Code. code.visualstudio.com
Hardware
16 GB RAM — labs 04–06 run three gateways plus a database, and Docker needs 8 GB of that to itself. Plus 20 GB free disk for images and volumes, measured inside WSL2 on Windows.

Platform notes

Windows
Install WSL2 and enable Docker Desktop's WSL2 backend. Run labs inside WSL, not PowerShell/Git Bash, and clone into your Linux home, never /mnt/c/…. Install curl via apt.
macOS
Apple Silicon is fully supported (Ignition publishes arm64 images). curl ships with the OS.
Linux
Docker Engine + Compose v2. Add your user to the docker group so you never need sudo.
Corporate laptop?
If Docker or Discord is blocked, or you're behind a TLS-inspecting proxy (Zscaler, Netskope, …), tell us at intake. Browsers can look fine while containers fail HTTPS.

04 · PREFLIGHT
The one task that matters most

Run the preflight check.

Once you've installed everything, fork the course repo and run its setup script. It starts with our preflight check, which validates every tool, pulls the course images (Ignition 8.3.6 and 8.3.8, TimescaleDB, and the GitHub runner), checks ports and bind mounts, and starts a test gateway. Most of the wait is image pulls.

$ mkdir -p ~/mustry-academy && cd ~/mustry-academy
$ gh repo fork Mustry-Academy/cicd-for-ignition --clone
$ cd cicd-for-ignition
$ ./course-setup.sh
Scan to open the
course repo
Windows: where you clone decides whether the labs work
Run this inside WSL, and note that first line: ~/mustry-academy is your Linux home. Keep your course repo there, never on your Windows drive (/mnt/c/…) — there, Windows decides file ownership, so it breaks in ways chown cannot fix and you end up needing sudo to edit your own project files. Our scripts refuse to run from /mnt/c and never need sudo. Check with pwd: it must not start with /mnt/.

The preflight writes preflight/preflight-report.txt. Paste it into #preflight-help on Discord so we can confirm you're ready. On failure, start with the script's suggestion, then preflight/troubleshooting.md in the repo.

Deadline
Please have a passing preflight at least two days before Day 1. Stuck at any point? Say so in #preflight-help and you get a 1:1 with the TA straight away.

Fill in the intake survey

05 · THE COURSE
What we'll cover

A typical four days

This is how the material runs over a typical four-day course, and each day builds on the last. Some cohorts spread the same content over more sessions or other adjustments are made.

01/ 04
Foundations & the Git mindset
By the end of Day 1, Git stops feeling like incantations and starts feeling like a tool you reach for without thinking.
  • Why version control matters for Ignition
  • Git internals, demystified
  • Branching strategies compared
  • Pull requests done right
  • Everyday Git workflows, hands-on
02/ 04
Collaboration & automation
The day you build the safety net you've always wanted: linters that fail loudly and pipelines that catch mistakes before they reach a gateway.
  • Validation and linters as a safety net
  • GitHub Actions: workflows, jobs, steps
  • Self-hosted runners
  • Ignition 8.3 file structure
03/ 04
Ignition-specific deployments
Everything the generic CI/CD books skip about Ignition: file layout, multi-gateway promotion, and what to leave on the cutting-room floor.
  • Image-based vs file-based deploys
  • Deploying the database with your code
  • Third-party modules
  • External JAR libraries
04/ 04
Ignition in the real world
Tying it together for the parts the demos never cover: live databases, real secrets, and a local loop you'll actually want to use after the course ends.
  • Multi-gateway
  • Configuration options explored
  • Secrets management, painlessly
  • Capstone brief
